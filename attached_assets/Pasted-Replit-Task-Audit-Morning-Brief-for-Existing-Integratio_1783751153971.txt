Replit Task: Audit Morning Brief for Existing Integration Health Summary Capabilities

Goal:
Determine whether Morning Brief already contains, partially contains, or can directly reuse existing integration health data before building any new summary widget.

This is an AUDIT-ONLY task.

Do not modify code.
Do not add components.
Do not add API routes.
Do not run code generation.
Do not change styling.
Do not create a checkpoint unless automatically required.

Keep the audit focused and credit-efficient.

Inspect:

1. Morning Brief page/component files

2. Existing data sources used by Morning Brief, including:
   - diagnostics health
   - integration health history
   - connected accounts
   - provider errors
   - recent system incidents
   - business health score
   - alerts
   - recommendations
   - quick actions

3. Existing frontend components that could already display:
   - healthy integration count
   - warning/error count
   - provider status
   - recent failures
   - last checked time
   - recommended action
   - link to System Diagnostics

4. Existing backend summary endpoints that Morning Brief already calls.

5. Whether Morning Brief already duplicates any data shown in:
   - Mission Control
   - System Diagnostics
   - Connected Accounts
   - Command Center

6. Whether the new Integration Health History endpoint is necessary for Morning Brief, or whether the existing current-health endpoint is sufficient.

7. Any existing alert, card, badge, or summary component that should be reused instead of creating a new one.

8. Whether Morning Brief currently has:
   - polling
   - stale-time settings
   - refresh controls
   - loading skeletons
   - error states

9. Any risk of introducing duplicate API calls if a new integration summary is added.

Deliverables:

A. Existing Morning Brief capability summary

B. Reusable components and hooks

C. Existing endpoints and query keys

D. Overlap with Mission Control, System Diagnostics, and Connected Accounts

E. Whether a new widget is needed

Classify as:

1. Already exists
2. Small extension only
3. Moderate implementation needed
4. New subsystem required

F. Lowest-credit implementation recommendation

G. Exact files likely to change in the next phase

Do not make any code changes.
Stop after reporting findings.

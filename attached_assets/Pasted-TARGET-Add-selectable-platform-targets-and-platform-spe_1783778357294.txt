TARGET: Add selectable platform targets and platform-specific content/media profiles to Content Autopilot.

IMPORTANT:
Follow the AI Edge audit-first workflow. Do not create a second platform registry, second capability model, or duplicate platform configuration.

PHASE 1 — AUDIT

1. Trace the production Content Autopilot route and component hierarchy.
2. Locate the canonical social platform registry and all capability fields currently available.
3. Locate the current platform cards, tips data, generation button, generation mutation, queue logic, and generated-content model.
4. Determine whether platform selection already exists anywhere in:
   - Publishing Center
   - AI Media Engine
   - campaign creation
   - social post composer
5. Search for existing media dimension, aspect-ratio, crop, thumbnail, safe-zone, or platform-format configuration.
6. Identify whether the backend generation endpoint currently accepts:
   - no platform list,
   - a fixed three-platform list,
   - or canonical platform IDs.
7. Report audit findings before implementation.

PHASE 2 — SELECTABLE PLATFORM CARDS

Convert the Content Autopilot platform cards into selectable generation targets.

Requirements:

1. Use canonical platform IDs.
2. Clicking a platform card toggles selection.
3. Selected cards show:
   - visible selected border
   - checkmark
   - “Included” or equivalent status
4. Unselected cards remain visible.
5. Disabled cards remain visible and explain the reason:
   - generation unsupported
   - connection required
   - approval pending
   - missing permission
6. Do not confuse generation capability with direct publishing capability.
7. A platform may be selectable for content generation even if publishing is draft/export-only.
8. Add:
   - Select all available
   - Clear selection
9. The Generate button must display the selected count, for example:
   “Generate for 5 platforms”
10. Disable generation when no eligible platform is selected.
11. Persist the last valid selection using a versioned localStorage key.
12. Normalize stored platform IDs against the canonical registry.
13. Keep persistence behind a small helper so Clerk metadata can replace localStorage later.

PHASE 3 — GENERATION REQUEST

1. Update the generation flow to send only selected canonical platform IDs.
2. Preserve existing working generation behavior.
3. Reject unsupported or unknown IDs server-side.
4. Do not send disconnected or capability-ineligible platforms unless the workflow explicitly supports draft generation without connection.
5. Ensure generated results are keyed by canonical platform ID.
6. If the API contract must change:
   - update OpenAPI first
   - update Zod schemas
   - regenerate clients
   - update all consumers
7. Do not fabricate support for a platform whose backend generation template does not exist.

PHASE 4 — PLATFORM CONTENT PROFILES

Create or reuse one shared platform content-profile configuration keyed by canonical platform ID.

Each profile may define:

- caption length guidance
- tone
- hashtag behavior
- CTA style
- title support
- description support
- keyword strategy
- link behavior
- local SEO guidance
- generation template identifier

Do not hard-code these rules inside page JSX.

Initial profiles should cover currently supported generation platforms, including as applicable:

- Facebook
- Instagram
- Google Business Profile
- YouTube
- TikTok
- LinkedIn
- Pinterest
- Nextdoor

PHASE 5 — PLATFORM MEDIA PROFILES

Create or reuse a shared media-format configuration keyed by platform and placement.

Support placement-specific formats rather than one size per platform.

Initial format types should include, where applicable:

- square 1:1
- portrait 4:5
- vertical 9:16
- landscape 16:9
- Pinterest 2:3
- wide 1.91:1

Each format profile should define:

- canonical format ID
- aspect ratio
- recommended pixel dimensions
- safe-zone inset
- placement label
- whether text overlay is recommended
- whether crop-only reuse is acceptable

Do not scatter dimensions across components.

PHASE 6 — MASTER ASSET AND VARIANTS

Design the data model so one campaign can have:

- one master creative concept
- one source asset
- multiple platform-specific variants

Each variant should be able to reference:

- master/source asset ID
- platform ID
- placement ID
- width
- height
- aspect ratio
- crop position
- safe-zone metadata
- overlay layout
- approval state

Do not blindly crop a finished text-heavy image.

Preserve important subject matter, logo, headline, and CTA within each placement’s safe zone.

Do not build a full advanced image editor in this task unless one already exists and can be reused.

After generation, show platform-specific previews.

Requirements:

2. Render each preview in its actual aspect ratio.
3. Label the platform and placement clearly.
4. Show platform-specific caption fields.
5. Show draft/export-only status where direct publishing is unavailable.
6. Allow review before queueing or publishing.
7. Keep the UI responsive.
8. Preserve the current dark executive design system.

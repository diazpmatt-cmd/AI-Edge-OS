PHASE 3 — DEFINE THE CORRECT STATE MODEL

Content Autopilot must distinguish between these separate concerns:

1. Platform exists in the canonical registry.
2. Platform is visible in the product.
3. Platform is connected for the current tenant.
4. Platform is approved or pending provider approval.
5. Platform supports content generation.
6. Platform supports direct publishing.
7. Platform supports scheduling or queueing.
8. Platform is healthy or unhealthy.
9. Content has been generated for the platform.
10. Content is queued, scheduled, published, failed, or not queued.

Do not collapse these states into one boolean.

Use existing types, selectors, helpers, and components wherever possible.

Do not create a second normalized state model if Publishing Center already owns one that can be reused or safely generalized.

The next implementation order should be:

1. Validate the retained C7 repository layer

Audit lib/db/src/discovery-c7-repository.ts before building on it. Confirm its schema, tenant predicates, uniqueness constraints, lease/claim behavior, and whether it matches the finalized C7 schedule model. Do not assume the old partial implementation is correct just because it is inert.

2. Build schedule-domain primitives

Add the provider-independent core first:

schedule types and lifecycle;
timezone/DST-safe next-run calculation;
overlap policies;
catch-up policies;
deterministic occurrence IDs;
schedule validation;
automation configuration, disabled by default.

These should be pure and heavily tested before runtime wiring.

3. Build leadership and claiming

Implement database-coordinated scheduler leadership and atomic due-schedule claims. This is the critical multi-instance safety boundary.

4. Build the scheduled dispatcher

The dispatcher should resolve an occurrence and invoke:

await discoveryExecutionService.execute({
  clientId,
  correlationId,
  mode,
  costCeilingUSD,
  discoveryContext,
  plan,
  actor: {
    actorType: "system",
    actorId: scheduleId,
  },
});

It must not duplicate lease, cancellation, audit, pipeline, or finalization logic.

5. Add a single-tick scheduler

Create a directly testable runSchedulerTick() that:

acquires leadership;
finds and claims a bounded set of schedules;
dispatches each independently;
records outcomes;
returns a structured summary.

Do not start timers in tests.

6. Add conservative stale-run recovery

Wire existing C6 recovery primitives for expired leases, abandoned claims, and interrupted nonterminal runs. Never replay chargeable provider calls unless safe idempotency is proven.

7. Add runtime integration last

Only after the pure scheduler and dispatcher tests are green:

add the disabled-by-default loop;
start only when explicitly enabled;
stop cleanly on shutdown;
expose sanitized health state.

One thing should be corrected in the handoff language: C7 has not yet begun just because discovery-c7-repository.ts exists. Treat that file as untrusted partial groundwork until it passes the new C7 audit and tests.
